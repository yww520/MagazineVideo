# 英文播客杂志刊 📖

把一集英文播客，收成一本可以竖着翻看的中文杂志短片。

粘贴 YouTube 链接 → 读页面、抓字幕、用中文写简介 → 勾你喜欢的段落 → 套上杂志刊头 → 导出 3:4 成片 → 一键填到小红书或抖音发布页。全程在本机完成。

---

## 这是什么 ✨

英文播客信息密度高，但很长、是英文、也不适合直接发短视频平台。这个项目做的是中间那一层：

- 先当编辑：把一集节目读成中文简介、通篇概括、分段观点
- 再当美编：把选中的片段装进杂志页，烧上刊头、中英字幕和珊瑚色高亮
- 最后当发行助理：打开网页发布页，帮你上传成片、填好标题和介绍，发不发由你点

成品比例是 **3:4（1080×1440）**，适合小红书、抖音这类竖版信息流。

---

## 能做什么 🧩

| 能力 | 说明 |
| --- | --- |
| 刊库 | 所有提炼过的节目都留在首页，封面点进去就能回看 |
| 中文简介 | 页面介绍、原章节（译成中文）、通篇概括、分段核心观点、一句话 |
| 选段包装 | 整片，或勾若干段按顺序拼接 |
| 两套杂志壳 | 暖奶油编辑风 / 墨绿刊印冷感风 |
| 成片回看 | 简介页折叠列表，点开看播放器和该段观点 |
| 续作 | 同一支节目可以反复包装不同段落，不覆盖旧成片 |
| 原片缓存 | 第一次包装才下全片，之后只裁切 |
| 发到平台 | 小红书、抖音网页发布页：上传 + 填文案，不代点发布 |

## 使用流程 🚶

### 1. 放进刊库 🔗

首页粘贴 YouTube 链接，点「开始分析」。这一步**只读页面、封面和字幕**，不下载音视频。

同一条链接再次提交，会打开已有存档，不会重复提炼。

### 2. 读简介 📝

分析完成后进入简介页，从上到下是：

- 封面、中文译名、原标题、频道、时长
- 已包装成片（可折叠）
- 页面介绍
- 原页面章节（中文标题 + 原时间码）
- 通篇概括
- 分段核心观点
- 一句话

确认没问题，再「继续包装新段落」。

### 3. 勾段落、填刊头 ✅

刊头页可以：

- 勾「整个视频」，或按主题勾若干段（多段按勾选顺序拼接）
- 改刊头四项：视频主标题、原英文名、节目名、视频地址
- 选杂志模板

主标题会跟着勾选段落走；太长会先截一版短刊头，你仍可手改。

### 4. 生成杂志片 🎬

点「开始生成」。本机依次：套模板 →（必要时）下全片并缓存 → 按段落裁切拼接 → 按条译中文字幕 → 去滚动叠句 → 珊瑚色高亮 → 渲染导出。

成片在 `videos/<节目目录>/dist/`。简介页可直接播放，也可以打开文件夹。

### 5. 发到小红书 / 抖音 🚀

成片行上有「小红书」「抖音」：

1. 弹出本机浏览器，打开对应创作者发布页
2. 第一次请在窗口里登录，登录态留在本机
3. 自动上传成片，填好标题和介绍
4. **暂存或发布请你自己点**，项目不会代发

介绍文案：分段用该段核心观点，整片用「页面介绍 + 通篇概括」；下面补原视频标题和频道，**不带视频链接**（平台容易限流）。标题按平台字数截：小红书 20 字，抖音 30 字。

网页创作者中心 ≠ 手机 App 草稿箱。平台改版或弹出验证时，窗口会留着给你手改。

## 本地怎么跑 💻

需要：

- Node.js 18+
- `yt-dlp`（`brew install yt-dlp`）
- `ffmpeg` / `ffprobe`（`brew install ffmpeg`）
- [302.ai](https://302.ai) 的 API Key（概括、按条翻译、珊瑚高亮）
- 页面完全没有字幕、又要包装整片时：本地 `faster-whisper`（`python3 -m pip install --user faster-whisper`）

```bash
cp .env.example .env
# 填写 LLM_API_KEY，按需改 LLM_MODEL
npm install
npm install --prefix web
npm run dev
```

浏览器打开 [http://127.0.0.1:5173](http://127.0.0.1:5173)。接口在 `8787`。

`.env` 示例：

```
LLM_BASE_URL=https://api.302ai.cn/v1
LLM_API_KEY=
LLM_MODEL=gemini-3.8-flash
PORT=8787
```

国内请用 `https://api.302ai.cn/v1`。改 `.env` 后要重启一次 `npm run dev`。

YouTube 下载若 403，可在 `.env` 里配 `YTDLP_COOKIES` 或 `YTDLP_COOKIES_FROM_BROWSER`。

## 文件架构 🗂️

只看目录在干什么，不必对着源码翻。

```
MagazineVideo/
├── web/                      前端：刊库、简介、刊头、制作进度
├── server/                   本地 API：分析、包装、发布页助手
├── magazine-grade-video/     杂志壳（两套模板）和渲染脚本
├── videos/                   每条成片一个目录（模板副本、字幕、导出 mp4）
├── data/jobs/                每支节目的存档（简介、封面、字幕、原片缓存）
├── ExtractPrompt.md          提炼用的编辑提示词
├── .env                      本机密钥与模型（不要提交）
└── README.md
```

**前端 `web/`**  
首页刊库、简介页、刊头页、分析 / 制作进度。Hash 路由，刷新不会丢当前节目。

**后端 `server/`**  
读 YouTube 页面与字幕、按提示词提炼、建议刊头、裁切拼接、翻译、渲染、打开小红书 / 抖音发布页。

**杂志壳 `magazine-grade-video/`**  
暖奶油、墨绿两套 3:4 版式。包装时复制到 `videos/` 再填刊头和字幕，不改壳的整体结构。

**存档 `data/jobs/<id>/`**  
`job.json`（简介与成片清单）、封面、分析用字幕；第一次包装后还有 `source/media.full.mp4`。登录态在 `data/xhs-profile/`、`data/dy-profile/`，已忽略，不进 git。

**成片 `videos/<Slug>/`**  
该次包装的 Remotion 工程和 `dist/` 里的 mp4。删成片只动这一份，原片缓存还在。

## 功能设计亮点 💡

### 先当编辑，再动刀 ✂️

分析阶段不下音视频。只拿页面介绍、最高清封面、章节时间码和原语字幕，就能写出一份能读的中文刊稿。长节目几分钟内先判断值不值得包装。

### 字幕当底稿，不是逐句复读 🎯

用 [ExtractPrompt.md](ExtractPrompt.md) 当编辑大纲：忠实保留发布者介绍，不把推广链接写进来；通篇概括要讲清问题、主张、主线和收获；分段大约 4–8 个主题，每段有观点、理由、案例和可执行动作。

YouTube 自动字幕常常是滚动双行。送给模型前会先去掉叠句，长节目才不会在半截被字数上限截断。章节标题译成中文，时间码与原页面一致。

### 同一支节目，可以出多本小册 📚

刊库按视频去重。第一次包装才下全片并缓存；之后换段落、换模板，只在本地裁切。成片追加保存，互不覆盖。简介页一条折叠一行，点开看片和该段观点。

### 勾选即刊头 🖋️

勾一段，主标题跟这段走；勾多段，按顺序拼。原英文名、节目名、地址自动带上，仍可手改。两套壳都是 3:4 杂志页：刊头、画面、中英字幕、珊瑚色高亮。

英文字幕只保留正在说的那一行；中文按条翻译，并去掉滚动残句。没有站点字幕时，整片包装会尝试本地 Whisper，不根据标题虚构分段。

### 送到发布页，不替你按下发布 ✋

小红书、抖音走官方网页发布页，本机浏览器 + 持久登录。只做上传和填表，不点发布、不点存草稿，也不进手机 App 草稿箱。文案不带原片链接，减少平台限流。

## 前端设计亮点 🎨

配色一直是奶油纸、墨色字、珊瑚色点缀，像一本薄杂志，而不是后台表格。

- **首页让给刊库**：顶栏是刊名，下面一条搜索栏，主体是封面格子
- **轻感新拟物**：同一层纸色上用很浅的凹凸，不用硬白块和大黑按钮
- **成片可折叠**：默认一行标题、时间和文字操作；点开才是播放器与观点
- **刊头页克制**：段落勾选和输入是浅浮起；模板未选透明，选中只加边框（墨绿不再铺深底，避免看起来像已选）
- **操作收轻**：发布、文件夹、删除做成文字链，主操作才用小胶囊

## 一些边界 📌

- 主要面向 **YouTube 英文播客**；没有字幕时，简介无法分段，包装整片才走 Whisper
- 小红书 / 抖音网页改版后，自动填表可能对不上，窗口会留着给你手改
- 改 `.env` 后记得重启开发服务
- 密钥、刊库存档、登录态都在本机，不要把 `.env` 和 `data/` 提交上去
